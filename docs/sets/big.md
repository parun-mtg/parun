# The Big Score census

The Big Score (BIG) cards not yet in the pool, and which wait on a
capability. Derived 2026-11-16 from MTGJSON's set list against `data/cards/`
(#8116). The set list is `data/decks/sets/big/all.txt`, which the suite reads,
so every card of the set stays in the pool.

BIG has 30 card names (MTGJSON 5.3.0+20261114; every printing `normal`); 4
were already in the pool, 26 missing.

## How it went

Finished 2026-11-16.

| Route | Cards | PRs |
| --- | --- | --- |
| Translated (census) | 1 | #8126 |
| Batches | 23 | #8133 (11), #8134 (12) |
| Behind a capability | 2, plus 0 from other sets | below |

- Census trend: the first dry run translated 1 of the 26 missing; 2 needed a
  capability. No batch sent a card on to a capability.
- Capability issues, hardest first: #8124 Esoteric Duplicator (#8135, a false
  gap: landed as card data with no engine change), #8125 Transmutation Font
  (#8137).
- Filed along the way: nothing beyond the fix issues.
- Fix issues: #8138 Transmutation Font (#8139), #8140 a duplicated claim walk
  (#8141).
- Audits: 2 of 4 capability or fix PRs; 1 found a rules defect. Reviewed
  inline #8141, clean; skipped the census, both batches and #8135 (card data
  only), each recorded on #8115.
  - #8137: the different-names sacrifice claim was a superset, so the engine
    offered Font with a Treasure counted both as mana and as a sacrificed
    token; fix #8138.
  - #8139: no rules defect; `Claim.filling` duplicated `apart`; fix #8140.
- Cost: 828 turns, 89.6M cache read, 1.10M cache write, 384k output over all
  7 unit PRs, 111 session-minutes in all. The finish unit's is on its own PR.
  Wall clock ~3.1h, from the tracker's opening to the last unit's merge
  (#8141), then the finish.
- `data/legalities.json`: regenerated by the finish, adding 33 rows (26 BIG
  cards and 7 cards other units added meanwhile). Its `parun ingest` run
  named no pool card as disagreeing with MTGJSON and wrote no card.
- Owner review:
  - Wire-format change: #8137 (`Sacrifice` gains a defaulted `differentIn`
    field, left out of the encoding when empty).
  - #8139: a new type, `Parun.Types.Selection`, on `Claim`, changing the
    affordability path every cast and activation takes. The audit noted the
    exact grouped check tries every different-named group of the required
    size when none survives (bounded, no defect).
